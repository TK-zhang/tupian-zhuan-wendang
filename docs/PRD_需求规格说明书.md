# 产品需求规格说明书 (PRD) - 图片与视频转文档群及AI重组织知识网络系统

## 1. 业务背景与问题定义

### 1.1 核心痛点与现实场景
1. **安全与合规受限场景**：
   - 金融银行内网、军工/涉密审计、政企封闭机房、外包堡垒机等环境中，DLP（数据防泄漏）全面阻断文件导出、剪贴板复制、USB 拷贝与直接外发。
   - 现场人员为了留存核心技术资产、操作规程或审计底稿，主要手段是**手机连续拍照、连拍截屏**，甚至通过**手机录屏/录像**一段连续操作或翻页过程。
2. **多形态零散资产难以利用**：
   - 传统 OCR 工具仅能产出无层级、无顺序的单页碎片文本，无法还原多页连贯性。
   - 用户拍摄时往往是**无序且发散的**：可能先拍了系统总览，再拍了部分配置，中间夹杂着白板草图、黑屏反光、重复拍摄的废片。
3. **关键痛点突破点：文档重组织与纠偏**：
   - **原始输入的“非结构化与混乱性”**：拍照者并非专业排版师，记录过程伴随着大量的顺序错乱、多处重复、关键步骤跳跃、模糊残缺。
   - **纯机械 OCR 的局限性**：机械还原只会把混乱的草稿原样搬到数字世界，毫无知识检索与阅读价值。
   - **AI 的真正核心价值**：在于**理解全局语义后的“知识重构与文档重组织（Document Re-organization）”**与**“跨模态纠偏修复（Contextual Rectification）”**。

### 1.2 系统愿景与核心定位
打造一个**“多模态输入（散乱图片/长视频/录屏） -> AI智能清洗与纠偏 -> 语义解构与重组织 -> 互联文档群（Doc Cluster）与知识网络”**的新一代知识工程自动化平台。

## 3. 功能需求规格 (Functional Requirements)

### 3.1 模块一：多模态多源摄入与预处理流水线
- **FR-101 多模态输入支持**：
  - **图片输入**：支持批量上传 PNG, JPG, JPEG, WEBP, HEIC 等。
  - **视频/录屏输入**：支持 MP4, MKV, MOV 等录屏或手机拍摄视频（可包含操作演示、PPT翻页、白板演讲）。
- **FR-102 视频关键帧提取与智能去重（Video-to-Keyframes）**：
  - 基于场景切换检测（Scene Cut Detection）与感知哈希（pHash / SSIM）技术，过滤运动模糊帧、鼠标滑动冗余帧、翻页过渡帧。
  - 提取出高清晰度、无重影的最佳文档/屏幕静止帧。
- **FR-103 视听双模态融合（Audio-Visual Fusion，视频特有）**：
  - 提取视频中的解说音频轨，通过 ASR（语音识别）生成带时间戳的解说文本（Transcript）。
  - 将解说文本与对应时间戳的关键帧进行时空对齐，弥补画面中省略的背景背景说明与操作意图。
- **FR-104 图像几何校正与抗噪增强**：
  - 透视变换拉平、屏幕摩尔纹消除、反光/阴影消除、字迹增强。

### 3.2 模块二：AI 驱动的文档重组织引擎（Document Re-organization Engine - 核心灵魂）
- **FR-201 散乱素材的智能主题聚类（Clustering into Doc Cluster）**：
  - 面对一批可能混杂了多个主题的图片/视频帧，AI 首先通读全局视觉与文本信息。
  - 自动识别文档边界（Document Boundary Detection），将单一输入集切分并聚类为**“文档群（Document Suite / Cluster）”**（例如：自动切分为《01_架构设计》、《02_接口规范》、《03_操作指南》）。
- **FR-202 逻辑结构化重组（Logical Outline Reconstruction）**：
  - 摆脱原始物理拍照顺序的束缚，按照技术文档或商业报告的最佳阅读习惯重建逻辑骨架：
    - 典型范式：`背景与目标 -> 总体架构 -> 核心模块详解 -> 异常处理/FAQ -> 附录规范`。
  - 识别并合并碎片要点：将多张图片上零散记录的同一配置项或属性归并到同一个表格或二级标题下。
- **FR-203 冗余消除与信息提炼（Deduplication & Synthesis）**：
  - 去除重复拍摄、重复展示的废话与多余信息。
  - 将多处反复补充修改的内容综合提炼为唯一的“最新生效版本”。

### 3.3 模块三：上下文智能纠偏与自愈系统（Contextual Rectification）
- **FR-301 视觉乱码与残缺自愈（Context-aware Error Correction）**：
  - 针对光照不均、小字模糊导致的 OCR 误识（如 `l` 错认为 `1`、`0` 错认为 `O`、变量名残缺），利用领域上下文（代码语法树、自然语言语法、术语库）进行逻辑纠偏。
- **FR-302 跨文档全局术语与实体一致性纠偏（Cluster-wide Entity Consistency）**：
  - 在整套文档群中构建全局实体词典（如某专有模块名 `DataPipelineOrchestrator`）。
  - 若某张模糊照片被识别为 `DataPipellne0rchestrator`，基于全局实体库自动将其纠偏还原。
- **FR-303 逻辑断裂与关键信息缺失提示（Anomaly & Missing Steps Warning）**：
  - 当发现操作时序或章节存在断层（例如从步骤 1 直跳步骤 3，或缺少接口参数说明），自动在文档中插入警示标注（如 `> [!WARNING] 此处疑似缺失步骤 2 的屏幕记录，建议核对补齐`）。

### 3.4 模块四：全球多语言与跨语种能力（Multilingual Engine）
- **FR-401 多语言混合高精度识别**：
  - 支持中、英、日、韩、德、法、俄等 50+ 种主流语言的高保真混合识别。
  - 精准区分自然语言、专业术语缩写与代码关键字（保留原本大小写与格式）。
- **FR-402 跨语言术语对齐与检索**：
  - 识别文档中中英文互译混用的实体（如“网关服务”与“API Gateway”），打通二者映射关系。
- **FR-403 可选智能跨语种转换/双语对照**：
  - 支持将外文资料重组为中文结构化文档，或生成“原文与译文段落级对照”视图。

### 3.5 模块五：超链接与知识网络构建（Hyperlinks & Knowledge Mesh）
- **FR-501 文档内精细化锚点（Intra-Document Anchors）**：
  - 跨段落、跨章节跳转（“详见 2.3 节” -> `[2.3 节](#23-核心流程)`）。
- **FR-502 跨文档互联超链接（Cross-Document Hyperlinks）**：
  - 在文档群内，若文档 A 提及文档 B 的概念或章节，自动建立相对路径链接（`[接口说明](../02_接口规范/api.md#v1-user)`）。
- **FR-503 双向链接与知识图谱拓扑（Obsidian Wikilinks & Graph）**：
  - 生成 `[[双链]]` 语法，并输出文档群的关系依赖网络（Mermaid 图谱或 JSON 拓扑结构）。

## 4. 关键指标与验收标准 (KPIs & Acceptance Criteria)

1. **重组织合理性评分**：经 AI 重组后的文档群大纲逻辑通顺度达标率 > 90%（由人工阅读体验评估）。
2. **术语纠偏准确率**：跨文档专有名词与标识符纠偏准确率 > 95%。
3. **视频关键帧提取压缩比**：在无信息丢失前提下，将长视频冗余帧压缩率达到 95% 以上（仅保留有效信息帧）。
4. **超链接精准度**：文档内锚点与跨文档超链接正确跳转率 > 92%。
