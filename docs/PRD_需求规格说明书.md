# 产品需求规格说明书 (PRD) - 图片重构成结构化文档与知识链接系统

## 1. 业务背景与问题定义

### 1.1 核心痛点场景
1. **安全与合规受限环境**：金融银行、军工研究所、涉密项目审计现场、外包开发堡垒机中，所有外发文本复制、USB 导出、截屏剪贴板均被禁用（DLP 监控）。工作人员为了将内部操作手册、架构规范或合同条款带出学习或备份，唯一通道为物理拍照或离线截屏。
2. **纸质散页与档案扫描件**：历史上沉淀的大量技术白皮书、学术报告、多卷宗合同仅有照片扫描件，各章节、各文件散落为成百上千张图片。
3. **现有工具局限性**：
   - 通用 OCR（如微信识图、常规百度/白描 OCR）：只能给出纯文本流，丢失格式、表格混乱、数学公式全崩，且对“页 1 接 页 2”跨页完全无感。
   - 现存 PDF/文档还原工具：针对单张图片往往单独处理，没有“**全局文档集合**”的概念，完全无法建立多文档之间的交叉引用网、互为补充的超链接体系。

### 1.2 目标定位
提供一套面向“图片合集/相册”的端到端自动化重构系统。输入一批散乱的图片，输出一个整齐划一、格式精美、互相关联的**数字知识库**。

## 2. 核心用户与典型使用场景

| 用户画像 | 典型痛点 | 期望输出 |
| :--- | :--- | :--- |
| **IT/架构师/工程师** | 在客户内网堡垒机中查看系统设计文档、API手册，无法复制，只能拍了几十张屏幕照片。 | 还原为带代码高亮、架构图截图、表格完整、API间可互相点击跳转的 Markdown/Docx 文档。 |

| **科研/学术人员** | 在图书馆拍摄了论文及其参考文献、附录补充材料。 | 识别 LaTeX 公式，文献引用处 `[1]`、`[2]` 自动生成指向对应附录或参考文献的锚点超链接。 |

## 3. 功能需求规格 (Functional Requirements)

### 3.1 模块一：输入管理与预处理（Input & Preprocessing）
- **FR-101 多源图片批量载入**：支持本地文件夹导入、ZIP 压缩包解压导入，格式支持 PNG、JPG、JPEG、WEBP、HEIC。
- **FR-102 图像几何矫正与增强**：
  - 透视变换与倾斜校正（针对手机拍摄的角度偏斜）。
  - 阴影、摩尔纹（屏幕纹）、反光消除。
  - 局部对比度增强（确保小字清晰）。
- **FR-103 智能归档与页面重组**：
  - 页面去重（防止同个页面重复拍了多张模糊与清晰的照片）。
  - 文档自动切分（检测到不同背景、文档标题页或明显风格突变时，切分为不同文档集合）。
  - 自动页码识别与拓扑排序（结合提取到的页码及上下文逻辑流动排序）。

### 3.2 模块二：多模态内容识别与单文档结构化（Single-Doc Structured OCR）
- **FR-201 标题与大纲体系重建**：精准判断 H1~H6 标题，自动生成目录层级树（TOC）。
- **FR-202 跨页内容智能缝合**：
  - 自动检测并剔除“页眉”、“页脚”、“装订线标记”、“水印”。
  - 识别跨页断行断句（如上一页末尾“系统架构包括以...”，下一页开头“...下几个关键模块”），实现无损平滑拼接。
- **FR-203 复杂多元素高保真还原**：
  - **表格（Tables）**：提取为标准 Markdown 表格或带合并属性（rowspan/colspan）的 HTML 表格。
  - **公式（Math Equations）**：行内公式 `$E=mc^2$`、块级公式 `$$...$$` 还原为标准 LaTeX 语法。
  - **代码块（Code Blocks）**：识别编程语言并格式化缩进。
  - **视觉资产提取（Visual Figures）**：自动检测文中的流程图、架构图、插图，从原图高清晰度裁切，保存到 `./assets/` 并在文档对应位置插入 `![图名](./assets/xxx.png)`；对于简单的时序图/流程图，可选尝试转为 Mermaid 代码。

### 3.3 模块三：链接与知识网络重构引擎（Linking & Knowledge Mesh Engine - 核心特色）
- **FR-301 文档内局部跳转链接（Intra-Document Anchors）**：
  - 识别正文中如“详见 2.1 节”、“如图 3 所示”、“见下方表格 1”、“参考附注 [3]”。
  - 自动为目标段落/图表生成标准 Markdown 锚点（如 `[2.1 节](#21-系统架构)`）。
- **FR-302 跨文档显式引用自动解析（Inter-Document Explicit Links）**：
  - 识别正文中对其他文档的显式引用，如“参照《数据库设计规范》第 4 章”、“详见用户操作手册.pdf”。
  - 扫描整个输入批次识别出的全部文档库，通过模糊字符串匹配与语义对齐，自动生成相对路径超链接，例如 `[《数据库设计规范》第 4 章](./数据库设计规范.md#4-表结构定义)`。
- **FR-303 实体识别与双向链接（Wikilinks & Bidirectional Links）**：
  - 针对核心业务术语、接口名称、模块名词，支持生成 Obsidian 风格的双链 `[[术语/模块名]]`。
  - 自动输出全局文档关系图谱（Graph Topology），提供直观的可视化依赖树。
- **FR-304 悬空引用与外部引用标记（Dangling & External Links）**：
  - 若引用的文档/网址未包含在本次图片集中，自动标记为“外部待补全引用”或保留显式纯文本/URL，避免破坏用户阅读连贯性。

### 3.4 模块四：输出导出与交付形态（Output & Delivery）
- **FR-401 Obsidian Vault 知识库格式**：
  - 输出结构化的文件夹体系、assets 附件目录、带 FrontMatter (YAML) 元数据的 Markdown 文件。
- **FR-402 通用 Markdown 目录树**：
  - 纯净 Markdown 文件，图片采用相对路径，适用于 GitHub / Notion / VS Code 预览。
- **FR-403 结构化 JSON 中间态**：
  - 导出 AST（抽象语法树）或 JSON 数据，方便后续二开或接入其他企业知识库系统。

## 4. 非功能性需求 (Non-Functional Requirements)

1. **准确率指标**：
   - 文本识别字符准确率（CER）要求 > 98%（正常光照与清晰度下）。
   - 标题层级判断准确率 > 95%。
   - 表格行列还原无错位率 > 92%。
   - 跨文档显式引用链接召回与对准准确率 > 90%。
2. **可扩展性与模块解耦**：
   - 图像预处理、大模型提取、链接对齐三层解耦，支持热插拔不同的视觉模型（如开源 Qwen-VL、MinerU 与云端商业大模型）。
3. **隐私与离线兼容度考量**：
   - 考虑到场景往往是“防泄密环境带出的资料”，需具备在本地 Ollama/vLLM 部署私有化大模型的兼容能力，避免二次泄密风险。
