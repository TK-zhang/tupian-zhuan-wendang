# 核心迭代 PRD - Iteration 3：无序素材聚类、动态大纲推导与重组织

## 1. 迭代概述与交付目标

### 1.1 业务诉求
用户在实际业务场景中（如驻场外包、封闭机房、研讨白板）拍摄的照片往往是**高度散乱、顺序颠倒、多主题杂糅**的（例如一次性导入的 40 张照片中，既有数据库 DDL 表结构，又有网络拓扑草图，还夹杂着部署操作命令行）。
单纯按文件名或拍摄时间串联会产生完全无法阅读的混乱垃圾文档。
Iteration 3 的核心使命是赋予系统“全局思考与重组织能力”：自动进行**多主题分卷聚类、专业树状大纲推导、多源重叠碎片内容去重融合**，以及生成跨文档/跨章节的**显式超链接网络**。

### 1.2 阶段验收核心指标
1. **多主题聚类准确率 (Purity Score)**：混杂 2~4 个独立主题的 30~50 张无序照片，分卷聚类纯度 $\ge 90\%$；
2. **大纲结构逻辑性评分**：推导出的章节树（Level 1~4）逻辑跳跃率 $\le 0.15$（无同名并列冲突，无倒挂逻辑）；
3. **碎片信息去重有效率**：同一配置项在不同照片中重复出现时，合并去重准确率 $\ge 92\%$；
4. **内部跳转锚点解析成功率**：文本中出现的“见第 X 节”、“如图 Y 所示”转为有效内部超链接的命中率 $\ge 95\%$。

## 2. 详细功能需求规格 (Functional Requirements)

### FR-301: 全局多模态多维特征提取 (Global Semantic Feature Extraction)
- **处理逻辑**：
  - 针对导入素材包中的每一张图片，提取轻量级稠密文本特征向量与版面视觉摘要；
  - 提取关键语义元数据：页面主要实体词集合（Named Entities）、核心标题候选（Title Candidates）、图表类型标记（架构图/时序图/代码/表格）；
  - 建立内存特征矩阵，用于后续无监督距离计算。

### FR-302: 密度自适应主题聚类与分卷器 (Density-based Topic Clustering)
- **处理逻辑**：
  - 采用改进型层次凝聚聚类（Hierarchical Agglomerative Clustering）或 HDBSCAN 算法；
  - 引入**语义亲和度衰减函数**：综合评估文本语义相似度与版面风格相似度；
  - **自动决定文档分卷数**：无需用户硬编码指定生成几篇文档，系统根据语义距离悬崖自动切分为独立文档单元（如《01_系统总体架构设计.docx》、《02_数据字典与接口规范.docx》）；
  - **异常孤岛过滤**：对于完全不相关的偶发素材（如生活拍照、纯黑废片），判定为孤立离群点（Outlier），隔离并提示用户，严禁强行拼入文档。

### FR-303: 树状专业逻辑大纲推演与重构 (Dynamic Outline Tree Induction)
- **处理逻辑**：
  - 针对分卷后的单文档素材子集，摆脱物理时间戳的束缚；
  - 检索行业金标准文档模版（如：`1. 概述与业务背景 -> 2. 系统总体拓扑 -> 3. 详细设计与数据流 -> 4. 关键配置与部署 -> 5. 异常处置与FAQ`）；
  - 将所有提取出的区块（Blocks）通过拓扑排序（Topological Sort）动态挂载到大纲树的对应枝叶节点下；
  - 自动为没有明确标题的孤立段落生成具有高度语义概括力的二级/三级标题。

### FR-304: 多源重叠碎片内容路由与去重融合 (Content Routing & De-duplication)
- **处理逻辑**：
  - **场景识别**：在演示或白板讨论中，多张照片往往包含相同界面的局部滚动或不同阶段的草图演进；
  - **Jaccard 语义重叠检测**：计算不同图片提取块之间的 N-gram 文本相似度与表格重叠率；
  - **最新状态覆盖策略**：若检测到相同配置项（例如同一 Nginx 配置文件在照片 A 中有 5 行，在照片 B 中有 8 行且包含更新时间），自动保留最完整或最新状态版本，剔除冗余前置草稿，并在注释中记录来源标记。

### FR-305: 显式跨段落与跨文档超链接注入 (Hyperlink & Anchor Injection)
- **处理逻辑**：
  - **文档内引用锚点**：扫描正文中出现的“见第 X 节”、“如前文架构图所示”等引语，通过全局标题 ID 倒排索引，自动编译为 Word 内部书签超链接（`w:hyperlink`）或 Markdown 锚点链接（`#heading-id`）；
  - **跨文档相对引用**：在同一文档群内部，若文档 A 提及文档 B 的核心术语，自动注入相对文件路径链接（`[详见数据字典](./02_数据字典与接口规范.docx#t_user)`）；
  - **Obsidian 双链生成**：在 Markdown 模式下，自动将全局核心实体包裹为 `[[双链实体名]]`，便于无缝导入知识管理软件。

## 4. 边界场景与异常防御矩阵

| 边界场景 | 现象描述 | 确定性防御方案 |
| :--- | :--- | :--- |
| **模糊边界跨主题素材** | 一张白板同时画了架构图和数据库表，两边各占一半 | 视觉切割引擎在版面分析阶段执行物理切分，将上半区路由至架构文档，下半区路由至数据库文档 |
| **循环引用超链接** | 文档 A 引用文档 B，文档 B 又引用文档 A 形成死循环 | 建立图拓扑环检测（Tarjan 算法），剔除循环边，仅保留单向一级主引用 |
| **页码时序严重倒挂** | 照片自带“第 15 页”标识，但在排序中被排在前面 | 抽取图像角落的页码/时间水印数字，将显式物理页码作为拓扑排序的强约束加权因子 |
