## 一、 需求分析与 PRD 撰写标准铁律 (PRD Granularity & Depth)

### 1. 拒绝粗放概括，单个 PRD 必须达到商业生产级深度
- **核心诉求**：严禁仅列几条原则性功能描述的“概念型 PRD”。一个严肃的商业级软件需求规格说明书必须具备自包含性、高度严谨性与确定性落地能力；
- **单篇 PRD 强制包含的核心要素**：
  1. **明确的业务与技术价值**：清晰阐述本模块为何必须存在、量化 ROI（如降低多少错误率、节省多少算力、规避何种审计风险）；
  2. **用户角色与典型业务场景（User Journeys）**：覆盖不同环境（涉密机房、会议研讨、日常扫描）下的输入特征；
  3. **分步骤算法与功能逻辑（Step-by-step Algorithms）**：按时序展开数据处理流程，明确具体算子与技术参数；
  4. **字段级数据字典与契约（Data Contracts）**：必须提供完整的 JSON Schema，明确字段名、数据类型、约束范围、默认值与业务释义；
  5. **强类型内部 API 签名（Python Interfaces）**：提供基于 `dataclass` / Pydantic 的类定义与函数入参/出参签名；
  6. **全量异常分类与错误码矩阵（Error Code Matrix）**：明确错误码（如 `ERR-PRE-001`）、触发条件、严重级别与降级容错机制；
  7. **边界场景与量化验收测试用例（Test Cases & KPIs）**：列出极端边界测试用例（如 0 字节、超大尺寸、全黑/全白、连字符冲突），并附带明确的输入与断言预期。

### 2. 流水线工程强制多阶段细拆，禁止“单体巨石 PRD”
- **核心诉求**：一条复杂的系统流水线（例如：从散乱图像到排版文档）体量极大，绝不可能在一个单一需求内做完，强行合写必然导致需求边界模糊、返工与实现崩溃；
- **细拆执行规约**：必须将大流水线横向解耦为多个高内聚、低耦合的子功能规格说明书（如：`PRD-01 图像预处理` $\to$ `PRD-02 版面分析` $\to$ `PRD-03 文本提取与断句自愈` $\to$ `PRD-04 核心DocAST` $\to$ `PRD-05 Markdown与资产导出` 等）。

### 3. “前紧后松、渐进演进”的敏捷迭代节奏
- **核心诉求**：
  - **马上要做的前序核心模块**：必须多拆几个，且每一个都要细到极致（商业级生产深度）；
  - **后续的扩展能力（视频、多格式、安全防护、知识库等）**：前期只需在全景总览中保留清晰的架构概要与业务定位，随着工程推进逐一展开细化编写，避免在早期过度空转推演未解锁的后期模块。

## 二、 技术文档行文风格规约 (Strict Technical Tone & No Metaphors)

1. **绝对剔除文学化比喻与口语化修辞**：
   - 严禁在技术文档、PRD、架构设计中使用任何文学化比喻、故事案例或市井俗语（如“相册火葬场”、“谁在白嫖谁在掏钱”、“核心金矿”等）；
2. **坚持冰冷、理性、客观的量化分析**：
   - 所有论述必须基于数学推导、算法边界、系统资源消耗（CPU/GPU/内存/I/O）以及商业经营模型（CapEx/OpEx/ARR/WTP），以客观、冷静的工程语言呈现。

---

## 三、 核心战略红线：早期阶段绝对禁止触碰大模型训练

1. **碰大模型训练必死（CapEx 与折旧陷阱）**：
   - 开源与闭源基座大模型迭代周期极快（每 3~6 个月发生代际跃迁），自行预训练或早期深度微调将面临高昂的算力集群资本支出（CapEx）以及基座折旧淘汰带来的沉没成本；
   - 领域微调极易引入灾难性遗忘，破坏通用图文对齐与代码推理泛化能力；
2. **坚定定位为“模型无关的推理编排与编译引擎”**：
   - 系统所有算力 100% 聚焦于前向推理、底层几何物理校正、确定性 AST 语法纠偏与排版渲染；系统支持接入任意前沿视觉多模态大模型，基座演进直接赋能系统而无需重新训练。

## 五、 产品功能双模划分与人机协同仲裁机制

1. **双模划分原则**：
   - **模式一：1:1 完全物理还原（Exact Physical Digital Twin）**：追求极致的绝对视觉还原，图标、位置、表格网格、代码完全无损原样映射；
   - **模式二：目标导向重组（Goal-Oriented Logical Synthesis）**：将会议白板、脑暴草图等多源杂乱素材，按照业务金标准大纲（如架构设计、接口说明、SOP）去重融合重组为目的明确的标准文档；
2. **人机协同仲裁红线**：
   - 当遇到歧义或低置信度（$< 0.85$）素材时，系统坚决**禁止无依据的大模型脑补幻觉**，必须在界面中提示黄色警告或呼出人工仲裁卡片，由人类最终确认。

## 六、 大模型能力边界认知与独立软件长期护城河

1. **大模型的制度性死穴：无法法律与审计担责（Liability Vacuum）**：
   - 通用大模型无论多么强大，本质上是概率分布拟合，存在不可消除的概率性幻觉（Hallucination）；
   - 在严肃政企与商业交付中，任何责任人绝不敢把身家性命押在没有证据依据的大模型回答上；
2. **持久工程壁垒**：
   - **Click-to-Source 双模态像素级坐标映射**：每个字符与数据项 100% 刚性绑定原始底片物理像素框，提供点击即反查原图的确定性免责证据链；
   - **确定性语法编译器**：AST 结构自愈与微软底层 OpenXML 规范编译；
   - **物理离线与安全准入**：合规断网运行与防逆向防护。

## 七、 软件全生命周期安全与涉密防逆向体系

1. **代码混淆与二进制机器码固化**：核心 Python 业务代码必须通过 **Nuitka / Cython** 编译为原生 C/C++ 二进制机器码（`.pyd` / `.so`），并执行调试符号剥离，反编译成功率强制为 0%；
2. **非对称硬件指纹离线 License 验签**：提取主板 UUID、CPU 序列号、主磁盘号等综合指纹加盐哈希，基于 **Ed25519 现代椭圆曲线数字签名**实现纯单机无网络离线验签；支持涉密 USB 物理加密狗；
3. **运行时防调试与内存即时置零**：检测到 x64dbg、IDA、Frida 等逆向分析工具附加时立即自毁退出；运算完成后的临时敏感张量和密钥强制调用 `SecureZeroMemory()` 物理清零；
4. **单调递增时钟防回拨**：防止离线机房篡改操作系统时间延长有效期；
5. **DoD 5220.22-M 涉密临时数据安全销毁**：任务完成或取消时，中间切片与 OCR 临时缓存强制执行军工级“三次覆写擦除”，杜绝取证软件物理恢复。

## 八、 知识库混合检索与问答反哺自愈飞轮

1. **四路统一多模态混合检索**：
   - 融合 SQLite FTS5 稠密全文 + HNSW 稠密语义向量 + 实体图谱三元组 + 视觉 BBox 坐标索引，兼顾精确技术代码查找与模糊意图推理；
2. **具身可信问答**：问答结果强制附带可点击的原图证据切片卡片；
3. **自愈反哺闭环（Closed-Loop Flywheel）**：
   - 用户在问答交互中发现错误并纠偏时，系统生成 RFC 6902 标准的 **AST Delta Patch**；
   - 补丁自动级联回写物理磁盘上的底层 Word/Markdown 文档及全局实体图谱，让文档库具备“越用越准确”的自演进能力。

## 九、 Git 私仓与版本管理铁律

1. **自动化创建 GitHub 私有仓库**：每个新工作区通过 `gh repo create "<中文业务仓名>" --private` 一键建立私有仓库；
2. **严禁频繁推送到远程私仓**：
   - 本地必须保持严谨的语义化 `git commit`（每次取得明确阶段性成果或重要文档落地时及时提交）；
   - **绝对严禁每次小改动就执行 `git push`**；仅在完成重大阶段性里程碑、任务收尾验证通过、或用户明确要求推送时，再统一推送到远程私仓。
